An agent that can't prove its work is a liability.

trust-no-agent is a discipline layer for AI coding agents: 11 markdown skills and a router that force fail-first tests, root-cause before fixes, receipts for every claim, and your sign-off before anything ships. It installs on the harness you already use.

Install the framework Read the source

why it exists

Agent output looks done. The tests pass, the summary sounds confident, the commit lands. Then the feature is wrong in a way nobody noticed, because nothing ever checked the claim against evidence.

The framework's answer is mechanical, not motivational. Every unit of work exits through verification gates that run as code. A claim without fresh evidence is rejected by the same hook that rejects a broken build.

Design reasoning, with the evals behind it: docs/design.md

the chain

Large work runs one unbroken path. Each stage proposes the next by name; you approve each crossing.

  1. breakpoint decisions surfaced before any code
  2. save-as a written spec with testable acceptance criteria
  3. fork-it tickets with blocking edges, sliced from the spec
  4. make-it-so build fail-first, repair loop capped at two rounds
  5. roast-my-code review along standards, spec, security
  6. ship-log append-only ledger, so the next session knows

Quick fixes skip the chain. Test-writing never does: a test that passes on first run is the exact anti-pattern this framework exists to catch.

four gates, exit zero or it didn't happen

node scripts/validate.mjs OK: 3 categories, 11 skills, no structural errors. node scripts/eval.mjs OK: 11 skills, invocation axis consistent, 0 warnings. node scripts/tickets.test.mjs OK: ticket-graph validator behaves as specified. node scripts/doctor.test.mjs OK: doctor behaves as specified. exit 0, or the pre-commit hook rejects the commit. CI runs the same four on every push.

Output above is the repository's real gate output.

the iron laws

01No work without verification. Evidence is output you read, not a feeling you hold.

02No fix without root cause. Five patches that don't stick are five guesses.

03No done claim without a receipt. The test had to fail first, then pass.

04No irreversible action without your sign-off. Commit, push, publish, delete: the agent proposes, you authorize.

what makes this different

Most agent frameworks optimize for speed. This one optimizes for trust, because the expensive failures are never about speed: they are the moment your agent said "done" and you believed it.

honest about what it can't do

A framework that demands receipts from agents holds itself to the same standard. Four limits, stated in its own README, unedited:

01It verifies testability, not intent. The spec gate forces specs to be testable, not true. Wrong intent stays possible; it just becomes cheap to catch.

02It does not make a weak model strong. It catches silent failures and forbids dishonest claims. Output quality still comes from the model, the harness, and the direction you give it.

03It does not enforce itself. Skills are text; a model's promise to comply is not evidence. The parts that never depend on the model are the mechanical ones: the four gates, CI, and the pre-commit hooks.

04It routes external skills, it does not vet them. Approval without audit is trust without evidence; the gates keep auditing everything an external skill produces.

The eval record behind this honesty: evals/live-results.md (4 harness rounds at 10/10, 3 at 9/10, each with its deviations disclosed) · docs/skill-vetting.md

install

npx skills add nadiwerk/trust-no-agent cp AGENTS.md WORKFLOW.md .

First npx run executes third-party code. Verify the package (npm view skills) before trusting it.

Skills land in your harness's skill-discovery directory; the cp adds the router, which no installer distributes. Without the router the skills sit inert: in the self-trigger eval, fresh agents loaded the mandatory skills 0 of 3 times without it.

Project already has its own router? Adoption runs as a guided interview and merges instead of copying. Per-harness paths, updates, de-adoption: docs/installation.md.
